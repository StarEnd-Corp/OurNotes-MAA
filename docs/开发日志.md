### ⚠️ 必读：MuMu 的 EmulatorExtras 截图在本机不可用

MFAAvalonia 打开时会自动检测设备，把 **MuMu 专用截图方式 `EmulatorExtras`** 当成最优解写进配置，但本机实测它**取不到画面**（`实时画面为空`，独立测试时连接直接返回 4000 / `cannot find any method to screencap`）。
实测可用的是纯 ADB 方式（`Encode`=2 / `RawWithGzip`=4，均为无损，出图 45KB~75KB，约 150ms/帧）。

已固定的实例配置 `config/instances/default.json`（**别让 GUI 覆盖**）：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `AdbDevice.ScreencapMethods` | `6` | `Encode(2) \| RawWithGzip(4)`，去掉 EmulatorExtras(64) |
| `AdbDevice.InputMethods` | `7` | `AdbShell(1) \| MinitouchAndAdbKey(2) \| Maatouch(4)`，去掉 EmulatorExtras(8) |
| `AdbDevice.Config` | `"{}"` | 不再传 MuMu extras 路径 |
| `RememberAdb` | `true` | 记住手工设定的设备参数 |
| `UseFingerprintMatching` | `false` | **关键**：为 `true` 时每次启动会按设备指纹重新检测并改回 EmulatorExtras |

`appsettings.json` 里 `NoAutoStart` 已设为 `True`：打开 GUI 不会自动开跑，等你手动点开始。
（若要恢复"打开即跑"，改回 `False`。）

### 二、把「下载了多少 / 领了什么」写进 MAA 日志（★ 核心机制）

**不需要任何外挂脚本**：MaaFramework 会把每次识别的完整结果（含 OCR 的 `text`、模板的 `score`/`box`）写进 `debug/maafw.log`。所以**只要把要记录的界面做成 OCR 识别节点**，数值就自动进日志。

实测证据（本机日志原文）：

```
reco [result={"algorithm":"OCR","box":[727,284,89,17],
  "detail":{"all":[{"box":[727,284,89,17],"score":0.997917,"text":"52.07MB"}],"best":{...}}}]
```

日志节点一览（`action: DoNothing`，只读不点，命中后按 `next` 继续原流程）：

| 节点 | 位置 | 记录内容 |
| --- | --- | --- |
| `LogDataDownloadSize` | 启动链 | 追加数据下载量（如 `52.07MB`） |
| `PLogPointReward` | 领TWG积分后 | 「获得奖励」弹窗文字（T.G.W CARD pt 数值） |
| `DLogDailyReward` | 领TWG每日奖励后 | 「领取奖励」弹窗文字（道具名/数量） |

⚠️ 两个奖励日志节点的 roi（[400,300,560,240]）是按弹窗大致位置估的，**待实机核对**；核对后日志里就会出现奖励原文。

另外 `tools/probe_nodes.js` / `tools/run_task.js` 现在都会设置 `maa.Global.log_dir = <项目>/debug`（+ run_task 开 `save_draw`），
所以**命令行直跑也产出与 GUI 相同的日志**；日志级别枚举见 `include/MaaFramework/MaaDef.h`（Off0/Fatal1/Error2/Warn3/Info4/Debug5/Trace6/All7，文件日志是全量，`stdout_level` 只管控制台）。

## 2026-10-03：0 火挂机的"自愈"跑法 + 结算屏顺序

实机连刷过程中遇到**偶发中断**（某几首歌只打了 47 秒就结算 → 疑似游戏侧打断；随后链停在 `LIVE FINISH` 屏）✗。
零点击探针验证 `ClickResultScreen` 识别正常（`text="LIVE FINISH"`），手动点中央也能推进 → 说明问题不在识别/点击，
而在**单链跑久了会因偶发原因提前结束**。

**结论：一直刷不停，就用看门狗套一层重启**（脚本 `grind_watchdog.sh`）：

```bash
while true; do
  node tools/run_task_override.js GrindStart '<override>' 2>&1 | grep -E "命中节点|任务结束"
  sleep 5
done
```

因为 `GrindStart.next` 的候选表覆盖了 主界面/标题/选曲/编队/打歌中/结算 各屏，**每次重启都能从任意屏接回来**
（实测打歌中途重启会命中 `WaitResult` 继续等结算 ✓）。停止 = 杀掉看门狗。

**结算屏顺序**（供后续核对）：
`打歌结束 → LIVE FINISH(评级页，无按钮须点中央 target[640,360]) → ♪图章 → 下一步×N → 结算总结(累计活动pt) → 再次演出`

### ★ 根因：开演前的「辅助模式」弹窗（2026-10-03 实锤）

打歌前游戏会弹 **「辅助模式：如果无法保持COMBO连击，使用辅助模式会更容易连上」** ——
**它没有可见按钮，必须点一下屏幕才消失**。没点掉时打歌会停在 `LIVESCORE 00000000` **无限干等** ✗
（实锤：卡了 6 分钟不动；手动点中央两下后分数立刻从 0 涨到 230 ✓）。

这解释了之前所有"莫名中断"：**"47 秒短歌"其实就是这个卡死状态被后续节点误判后草草收尾**。

已加节点 `GrindHelpModeDismiss`（OCR 守卫 `.*辅助模式.*|.*COMBO连击.*|.*更容易连.*`，target 点弹窗内中央），
挂在 `GrindStart` / `ClickTeamFlow` / `ClickLiveStart` / `WaitResult` 的 `next` **最前面**（每轮必经处优先检查）。

**诊断这类卡死的顺序**（已写进技能）：

### 二、选曲从 OCR 改成封面模板匹配

原先用 OCR 认歌名，但歌名是**滚动**的、框架还会丢字
（整行「これはぼくたちの生存のあらすじ」实测只读到「の生存の」），改为认封面。

**重要经验：模板图要「从游戏里裁」，不要拿原始美术图缩放。**

| 模板来源 | 最佳分 | 次高分 | 差距 |
| :--- | :---: | :---: | :---: |
| 原始美术图缩放到 69×69 | 0.7246 | 0.4506 | 0.27 |
| **直接从游戏截图裁 69×69** | **0.9215** | 0.4776 | **0.44** ✓ |

原因：游戏渲染封面时会做自己的缩放/滤波，只有「裁自游戏」才与它像素级一致。

可复用流程：
1. 用 OpenCV 在真实截图上做**多尺度匹配**（`cv2.matchTemplate` + `TM_CCOEFF_NORMED`，缩放扫 0.15~1.05），
   一次同时得出：目标在不在屏上、在什么位置、**游戏里的显示尺寸**。
2. 模板按 **720p 基线尺寸**保存（游戏里显示 103px@1080p → 模板存 **69px**）。
3. 阈值按**实测的两侧余量**定，别照抄 0.85：本例如封面在屏上时 0.80~0.92、不在时仅 0.43~0.48 → 取 **0.70**。

实测命中：`box=[212,439,69,69] score=0.8087`。

### 三、结算流程弹窗补齐（治 status=4000）

跑完整跳过链时结尾 `status=4000`，真因是游戏弹了链里没有的弹窗 →
该节点 `next` 全不匹配 → **next 全失败 = 任务结束**（游戏其实好好的，只是卡在弹窗上没人点）。

补了 `FLBondReward`（「羁绊奖励详情」，每个角色弹一个），并修正 `FLRankUp` 的点击位置
（原 (640,520) 偏高 140px 够不到底部 OK → 改为 (641,662)）。

**教训**：演出/跳过结束后的弹窗要**穷举** ——
跳过结果(OK) → 羁绊奖励详情(关闭，N 个) → RANK UP(OK，N 个) → 回编队页。
且**别用「命中的文字框中心」当点击目标**：这类弹窗标题在顶部、按钮在底部，点标题没用。

### 四、批量任务必须回主界面（重要）

6 个领取任务串跑时出现「只命中入口就 status=4000」，看着像链坏了，实际是
**上一个任务把游戏留在了第三种状态**（通行证页）—— 任务入口靠
`OnHome` / `OnPage` 两种状态起步，都不匹配就直接结束。

实测：把游戏退回主界面后，④任务奖励 / ⑤礼物盒 / ⑥录音室 **全部一次通过**。

规则：批量脚本里每个任务前先 `ensure_home()`（OCR 主界面特征，不在就按返回键退）。
另：给推进型节点补兜底时**优先用该页专属按钮**（如通行证任务页的「关闭」），
**别用通用主页图标** —— 很多页面也有它，盲点会导致中途提前退出，奖励反而领不全。
（本次 `pass_pt.json` 的断链就是这么修的：`PassClickTaskBtn.next` 末尾补 `PassDailyClose`。）
